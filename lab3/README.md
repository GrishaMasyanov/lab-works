# Лабораторная работа №3

## Описание проекта

Данный проект посвящен изучению принципов работы хэш-таблиц и их реализации на языке Java.

В рамках лабораторной работы были выполнены:

1. Реализация собственной структуры данных `HashTable` с использованием метода цепочек для разрешения коллизий.
2. Работа со встроенной коллекцией `HashMap`.
3. Реализация системы учета заказов интернет-магазина (вариант №7).

---

## Структура проекта

Проект состоит из двух основных частей.

### 1. Собственная реализация HashTable

Класс `HashTable<K, V>` реализует механизм хранения данных в виде пар «ключ-значение».

Основные компоненты:

- массив корзин (buckets);
- связные списки для хранения элементов;
- хэш-функция для вычисления индекса;
- обработка коллизий методом цепочек.

---

### 2. Система учета заказов интернет-магазина

Для демонстрации работы встроенной коллекции `HashMap` реализованы следующие классы:

#### Order

Класс содержит информацию о заказе:

- номер заказа;
- список товаров;
- адрес доставки;
- стоимость заказа.

#### Main

Главный класс программы, демонстрирующий:

- добавление заказов;
- поиск заказа по номеру;
- удаление заказа;
- вывод информации о заказах.

## Реализованные возможности

### Собственная HashTable

Реализованы основные операции работы с хэш-таблицей:

#### Добавление элемента

```java
put(K key, V value)
```

Добавляет новую пару ключ-значение либо обновляет существующее значение.

#### Получение элемента

```java
get(K key)
```

Возвращает значение по указанному ключу.

#### Удаление элемента

```java
remove(K key)
```

Удаляет запись из таблицы.

#### Подсчет количества элементов

```java
size()
```

Возвращает текущее количество записей.

#### Проверка на пустоту

```java
isEmpty()
```

Определяет наличие элементов в таблице.

## Разрешение коллизий

В проекте используется метод цепочек (Separate Chaining).

Каждая ячейка таблицы содержит связный список элементов.

При возникновении коллизии новая запись добавляется в список соответствующей корзины.

Схема работы:

```text
Index 0
Index 1
Index 2 -> [Order1] -> [Order2]
Index 3 -> [Order3]
Index 4
```

Такой подход позволяет хранить несколько элементов с одинаковым хэш-индексом.

## Использование HashMap

Во второй части лабораторной работы используется встроенный класс:

```java
HashMap<Integer, Order>
```

где:

- ключ — номер заказа;
- значение — объект класса `Order`.

Поддерживаются следующие операции:

### Добавление заказа

```java
orders.put(orderId, order);
```

### Поиск заказа

```java
orders.get(orderId);
```

### Удаление заказа

```java
orders.remove(orderId);
```

## Реализованные принципы ООП

### Инкапсуляция

Все поля класса `Order` объявлены как:

```java
private
```

Доступ к данным осуществляется через геттеры и сеттеры.

### Абстракция

Класс `Order` описывает только основные характеристики заказа и скрывает детали реализации хранения данных.

### Наследование

В работе использованы механизмы наследования стандартной библиотеки Java и коллекций Framework.

### Полиморфизм

Используются универсальные типы (Generics):

```java
HashTable<K, V>
```

что позволяет работать с объектами различных типов без изменения логики класса.

## Особенности реализации

### Generics

Собственная хэш-таблица реализована с использованием обобщений:

```java
HashTable<K, V>
```

что делает структуру данных универсальной.

### Работа со связанными списками

Для хранения элементов внутри корзин используются объекты:

```java
LinkedList<Entry<K, V>>
```

### Обработка коллизий

Все коллизии корректно обрабатываются методом цепочек без потери данных.
